SOPs were written for humans. Your AI needs AOPs.

The procedures that run your business were written for people to read and follow. As AI agents start doing the actual work, they need a version written for them. That version has a name now: the AOP.

The procedure your business runs on was written for a person

A standard operating procedure assumes a human is reading it. It assumes that person can interpret a vague step, ask a coworker when something is unclear, and use judgment to fill the gaps the document leaves open. That is fine when a person runs the process. It falls apart the moment you hand the same document to an AI agent and expect it to act.

An agent cannot run an SOP the way a person does. It needs the intent stated, the decision points named, and the actions made explicit. The procedure has to be written for the thing that will carry it out. For a growing share of routine work, that thing is now software.

What an AOP is

An AOP, or Agent Operating Procedure, is the agent-era successor to the SOP. Where an SOP tells a human how to run a process, an AOP is a procedure written so software can follow it step by step, with the judgment calls written down. It captures the intent, the decision points and the actions, things like book a job, check a warranty or update a record, rather than only describing them in prose.

It is an emerging term, pushed mainly by Decagon and also used by Skan AI and AthenaIntel. It is not yet a universal standard, and we do not pretend to have coined it. We use it because it names something real that is showing up across the AI space: the agent-runnable version of a procedure.

An example: booking a service call

Each step is a stated decision or action, rather than a sentence a person has to interpret:

  1. Confirm the address is inside the service area.
  2. Check the customer record for open jobs or warranties.
  3. Offer the next two open slots for that job type.
  4. Book it and send the confirmation text.
  5. Log it in the job system.

Anything outside the rules, such as an emergency, a complaint or a price question, goes to a person.

How to create an AOP

You do not start from scratch. You start from the SOP you already have and make it explicit enough for an agent to run. The steps:

  1. Start from the SOP. The written procedure your team already follows is your source of truth.
  2. State the goal. Name what a successful run looks like in one sentence, for example "book the customer into the right slot for their job."
  3. List the decision points. Write out every place a person would normally pause and judge: the checks, the thresholds, the if-this-then-that. An agent cannot guess these the way a person can.
  4. Define the actions and tools. Spell out the concrete actions and the systems they touch: look up the customer, check the calendar, book the job, send the confirmation.
  5. Set the guardrails. Decide what the agent must never do on its own and where it has to hand off to a person.
  6. Test and validate. Run it on real cases, compare against how a person handled them, and tighten the steps until it holds.

In short: an SOP describes the work for a person, and an AOP makes the same work runnable by an agent, with the judgment written down instead of assumed.

The honest part

AOP is early. The term is partly vendor-driven, and full autonomous agent operation is still a direction rather than a finished product you can buy today. We are clear about that on purpose. The practical move is to turn the SOPs you already have into agent-runnable procedures, start with the routine work, automate what is safe to automate, and keep a person on the hard cases. The agent earns more of the work as it proves it can run the work.

That is the difference between chasing a trend and building on one. The trend is agents. The thing you build is the procedure they run.

Common questions

What is an AOP?

An AOP, or Agent Operating Procedure, is a procedure written for an AI agent rather than a person. It is the agent-era successor to the SOP: a procedure written so software can follow it step by step, with the judgment calls written down. It is an emerging term, pushed mainly by Decagon and also used by Skan AI and AthenaIntel, and is not yet a universal standard.

Do I need to throw out my SOPs?

No. Your SOPs are the source. An AOP starts from the procedure you already have and makes the goal, the decision points and the actions explicit enough for an agent to run. Your team keeps the SOP. The agent runs the AOP.

Is AOP a real standard yet?

Not a universal one. AOP is an emerging, partly vendor-driven term as the market shifts from workflows to agents. We use it because it names something real, the agent-runnable version of a procedure, but we do not claim to have coined it, and we treat full autonomous agent operation as a direction, not a finished product.

Are AOPs the same as agent prompts or workflows?

Not quite. A prompt is a single instruction and a workflow is a fixed sequence of steps. An AOP sits between them: a written procedure with its decision points spelled out, so an agent can handle the branches a rigid workflow cannot, and stay consistent in a way a one-off prompt cannot.
